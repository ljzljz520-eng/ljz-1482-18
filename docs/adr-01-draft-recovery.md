# ADR-01：本地草稿恢复顺序 —— 先验证访问，后恢复草稿

## 背景

创作工作台是一个多项目、多成员、带深链接（`/projects/:id/sessions/:id?step=n`、素材链接、旧节点链接、历史导出链接）的 SPA。
用户在离线或会话过期时，编辑内容会以「待同步草稿」形式落在浏览器本地（localStorage，键含 projectId + sessionId）。

打开深链接时，草稿恢复有两种可选顺序：

## 方案 A：先恢复本地草稿，再加载服务器

流程：从 localStorage 读草稿 → 渲染编辑器 → 后台请求 `/sessions/:id` → 成功则对账，失败再收起。

问题：

1. **越权闪现（信息泄漏）**：权限已被收回（从成员中移除）或链接属于其他项目时，页面先把本地脚本内容渲染了出来。
   即使随后被 403 页面替换，内容已经进入 DOM / 截屏 / 读屏 / 浏览器缓存，构成实质泄漏。
2. **误导性等待**：用户看到的是“自己的稿子”，随后突然变成无权限页，会以为内容被平台删除。
3. **错误注入风险**：若本地草稿按 sessionId 单键存储（不带 projectId），甲项目草稿可能被乙项目的同 ID 场次读取。
4. **退役/迁移状态未知**：项目已退役、场次已被软删除、旧节点已迁移时，先渲染草稿再纠正，状态闪烁严重。

## 方案 B（采纳）：先验证访问，后恢复草稿

流程（`useScriptEditor.reload`）：

1. 携带 token 请求 `GET /api/projects/:pid/sessions/:sid`（后端同时校验：登录态 → 项目成员 → 资源归属项目 → 删除状态 → 退役状态）。
2. 请求未成功前，编辑器只显示骨架屏与“正在验证访问并拉取服务器脚本…”。
3. 请求成功后才读取本地草稿，并按基准版本对账：
   - 草稿 `baseVersion === 服务器当前版本`：恢复为「待同步」状态，顶部提示来源与时间，可一键丢弃。
   - 草稿 `baseVersion < 服务器版本`：不静默覆盖、不静默丢弃，进入显式**冲突**对话框。
4. 请求失败（403/404/410）：本地草稿**不渲染**，直接移入「隔离区」（quarantine），用户可复制/彻底删除，但系统不会自动写回服务器。

### 权限被收回时本地内容怎么处理

- **留在本机，进入隔离区**：403（成员移除/角色降为无权限）、404（场次/素材删除、跨项目 ID）、410（项目退役）分别标注原因。
- **不上传、不渲染、不合并**：隔离区只存在于当前浏览器；重新成为成员也不会自动恢复，必须用户显式决定。
- **可自救**：提供“复制草稿 JSON / 彻底删除”，避免数据被静默销毁，也避免泄漏。

### 等待体验

- 项目级：进入工作台先显示“正在验证项目访问权限并加载工作台…（先完成访问校验，再恢复本地草稿）”。
- 场次级：骨架屏 + “正在校验访问并拉取服务器脚本…”，不闪现任何草稿内容。
- 会话过期：全局 401 拦截器弹模态框，记录 `returnTo`（当前深链接），重新登录后回到原地址并重新走完整鉴权；未同步草稿留在本机。

## 结论

路由守卫（`RequireAuth`）只判断“有没有登录”，负责体验；**是否有权看到某个项目/场次/素材/快照，永远由后端每个读写接口判定**。
先验证后恢复，使本地草稿永远不会先于授权出现在页面上，“猜到 ID 不能绕过权限”。
