# ADR-02：异步导航代次隔离 & 保存/离开竞争状态机

## 1. 异步导航的目标代次（Generation）隔离

### 问题

用户快速在两个项目间切换：点开「项目甲」（慢网络），立刻切到「项目乙」（快网络）。
若请求“先到先得”地写入同一个 store，甲的 bootstrap 晚到时会把甲的项目名、场次列表、素材、脚本渲染到乙的 URL 页面上——**地址栏是乙，内容是甲**。

### 方案

`workbenchStore.loadProject(projectId)` 维护单调递增的 `generation`，并持有当前的 `AbortController`：

1. 每次切换：`generation += 1`，`abort()` 上一代请求，先清空数据进入 loading。
2. 请求返回后，**提交前**再次比对 `if (gen !== get().generation) return null`，过期代次的响应直接丢弃。
3. 场次脚本加载（`useScriptEditor`）使用独立的 `loadGen`，离场时 `loadGen.current++` 使迟到响应失效；组件用 `key={projectId:sessionId}` 重建，杜绝跨场次状态残留。
4. 旧节点解析（`LegacyRedirect`）同样带代次 + AbortController，快速切换不同旧链接不会跳错目标。

不变量：**地址栏的 projectId/sessionId、左侧选中项、右侧编辑对象三者永远指向同一代次的数据**。

## 2. 保存与离开竞争：已提交 / 待同步 / 冲突

### 三态定义

| 状态 | 含义 | 本地草稿 | 服务器 |
|---|---|---|---|
| `saved` 已提交 | 保存请求成功，版本号对齐 | 清除 | 有新版本 |
| `dirty` 待同步 | 有编辑但尚未成功提交 | localStorage 持久化（键含项目+场次） | 仍是旧版本 |
| `conflict` 冲突 | 本地基准版本落后于服务器当前版本 | 保留，baseVersion 更新为服务器版本待决策 | 已有他人新稿 |
| `saving` 提交中 | 请求在途（单飞，禁止二次提交） | 保留 | — |
| `error` | 403/410/网络错误等 | 保留 | 不变 |

### 乱序响应防护

- 每次保存分配递增 `saveSeq`；响应回来时 `if (seq !== saveSeq.current) return`，**只接受最新一次保存的响应**。
- `savingInFlight` 单飞：提交中按钮禁用、守卫拦截，避免同版本并发双提交（后端还有行锁 + 乐观锁兜底，见下）。

### 离开拦截（仅体验，不改数据）

- 站内导航用 `useBlocker`：dirty/conflict/saving 时弹确认，可“留在此页”或“带草稿离开”。
- 关闭/刷新页签用 `beforeunload` 提示。
- 守卫**绝不**触发保存、更不会在冲突时自动选 OVERWRITE。

### 冲突解决（必须用户显式选择）

1. **采用服务器版**：放弃本地待同步稿，清本地草稿。
2. **用我的本地稿覆盖**：以服务器最新版本为 base，携带 `mode=OVERWRITE` 与备注生成新版本（旧稿仍在版本历史可回溯）。该按钮只存在于冲突对话框中。
3. **暂不处理，保留本地**：继续以待同步状态留在本机。

导航守卫、自动重试、切场次等任何自动流程都不会调用覆盖接口——**禁止为导航自动覆盖服务器新稿**。

### 后端兜底

- `PUT .../script` 以 `(scriptId, version)` 唯一约束 + `SELECT ... FOR UPDATE` 行锁串行化版本递增。
- `baseVersion` 必须等于服务端当前版本，否则 `409 CONFLICT` 并回传服务器最新内容；首次保存必须 `baseVersion=0`。
- 并发首登时，ScriptDoc 用 create/P2002 兜底幂等化，保证“恰好一个成功，其余 409”，不会出现 500 或版本号双花。

## 3. 历史导出链接的不变量

`Snapshot` 行唯一绑定一个不可变 `ScriptVersion`。快照页只请求 `/snapshots/:id` 并渲染该版本，
**从不请求“最新脚本”**，因此脚本继续更新后，历史导出链接打开的依然是导出那一刻的内容，不会错误导向最新草稿。
