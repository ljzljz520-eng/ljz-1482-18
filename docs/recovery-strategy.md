# 导航授权与本地草稿恢复策略

## 1. 两种恢复顺序比较

| 方案 | 流程 | 优点 | 风险 | 本项目结论 |
|---|---|---|---|---|
| 先恢复本地草稿，再加载服务器 | 立即从 localStorage 渲染 → 再请求项目/场次 → 根据服务器结果纠正 | 首屏快；离线时也能看到内容 | 权限被收回、猜 ID、项目退役或旧节点未迁移时，私有脚本可能先泄露到错误上下文；快速切换项目时本地状态更容易串到错误页面 | 不作为私有工作台默认方案 |
| 先验证访问，后恢复本地 | 校验登录态 → 后端查询成员、项目状态、资源归属与版本 → 验证通过后读取服务器对象 → 最后按资源键恢复本地草稿 | 不会对无权限者渲染私有内容；本地草稿可和服务器版本比较；深链接错误边界明确；符合“守卫只负责体验，接口必须兜底” | 等待期间需要骨架屏和明确状态提示；离线可用性较弱 | **采用** |

实现顺序：

1. 路由守卫只判断是否有登录 token，并保留 `returnTo`，不把它当作授权结果。
2. `GET /projects/:projectSlug/workbench` 及所有子资源接口在后端重新加载成员关系。
3. 后端确认项目存在、成员权限有效、项目状态可进入、目标场次/素材属于该项目且未删除。
4. 访问通过后，前端才用 `userId/projectId/sessionId` 读取本地草稿。
5. 将草稿的 `baseVersion` 与服务器 `baseVersion` 比较，区分一致未提交、旧版本待处理、已封存待同步。

## 2. 权限被收回时如何处理本地内容

- 项目根访问、场次、素材或保存接口返回 `403/404` 时，前端不渲染该资源对应的本地脚本。
- 该资源的 localStorage 草稿会移动到独立的 `revoked` 分区，而不是直接删除：
  - 用户可能只是临时被移出项目；
  - 用户仍可在确认私有的情况下手动下载或删除浏览器内副本；
  - 应用不会自动把它恢复到任何项目页面。
- 对猜到 ID 的外部用户，后端返回不可区分的 404，不暴露项目名、成员角色、脚本或素材 URL。
- 重新获得权限后，用户必须重新打开同一资源，系统再依据项目与资源校验结果决定是否展示隔离副本；不会因登录成功就自动恢复。

## 3. 等待体验

- 授权确认前显示统一骨架屏：“正在验证项目访问并加载工作台”。
- 等待期间不填充服务器脚本，也不填充本地草稿，避免闪现错误内容。
- 快速切换项目时，每次导航递增目标代次，并通过 `AbortController` 取消旧请求；只有最新代次可提交结果。
- 子组件按项目与资源 ID 重挂载；迟到响应还会再次比较资源键，甲项目数据不能写入乙项目页面。

## 4. 保存与离开竞争

保存请求显式区分三种状态：

- **已提交 committed**：服务器事务已写入 `Session` 当前版本和 `ScriptVersion` 历史，本地草稿清除。
- **待同步 pending**：请求已发出但响应未确认。离开时草稿写入 localStorage 并标记 `sealed`，页面用浏览器 `beforeunload` 提醒。
- **冲突 conflict**：本地 `expectedVersion` 与服务器当前版本不一致。接口返回服务器新稿和作者，前端只提供“使用服务器稿”或“生成人工合并副本”，不会为了导航、重试或响应乱序自动覆盖服务器新稿。

每个保存请求带递增 token：迟到响应只更新自己的队列记录；若它已不是当前资源的最新请求，不允许改写当前编辑器、标题、步骤或冲突状态。

## 5. 深链接与历史快照

- 项目：`/w/prj-*`
- 场次：`/w/prj-*/sessions/ses-*?step=outline|script|review`
- 素材：`/w/prj-*/assets/ast-*`
- 导出列表：`/w/prj-*/exports`
- 快照：`/w/prj-*/exports/exp-*`

非法项目、场次、素材、导出 ID 在前端格式校验阶段就展示错误页；格式正确但不属于当前项目、已删除或无权限，仍以后端 404/403 为准。

历史导出是冻结快照，拥有独立 `exp-*` 链接和快照内容。打开旧链接时只读取该快照，不跳转当前场次草稿；项目退役或原场次删除后，成员仍可读取自己有权访问的快照。
